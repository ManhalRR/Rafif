| Вопрос | Результат | Интерпретация |

## Воспроизведение расчётов

Нужен **Python 3.11+**. Установка Power BI или Excel для расчётного конвейера не требуется.

```bash
git clone https://github.com/ManhalRR/Rafif.git
cd Rafif
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate
python -m pip install -r requirements.txt
python analyze.py
```

Первый запуск загружает официальный XLSX UCI. SHA-256 проверяется до расчётов; неожиданный источник останавливает выполнение. Скрипт создаёт `data/portfolio.sqlite`, синтетический CSV и `results/`. SQL выполняется в SQLite; переносимость синтаксиса на PostgreSQL/Greenplum не заявляется. Опубликованные результаты можно сверить с локальной пересборкой.

Конвейер: **XLSX → нормализация → SQLite / SQL → независимая сверка pandas → CSV / JSON → отчётность**.

В архиве «Продажи / CRM / A/B» дополнительно находятся генераторы PDF/HTML, Excel и PBIP, исходники модели, CRM-кейс и готовые отчёты. Минимальные зависимости — `requirements-core.txt`; полный набор — `requirements.txt`. Excel пересобирается общедоступным `openpyxl`: `python build_workbook.py`. Node.js и закрытые пакеты для этого не нужны. Генератор PDF автоматически ищет Arial/DejaVu Sans или принимает `RAFIF_FONT_REGULAR` и `RAFIF_FONT_BOLD`.

[Новая Excel-книга](downloads/Retail_Analytics_Openpyxl.xlsx) собрана через openpyxl, затем пересчитана и проверена в Microsoft Excel: итог £8 587 247,02, 17 582 заказа, Германия £199 330,67 / 410 заказов, M1 19,94%, пустые будущие окна. [Протокол](downloads/Excel_Openpyxl_validation.json). Исходная [опубликованная книга](downloads/Retail_Analytics.xlsx) сохранена отдельно. При локальной пересборке openpyxl записывает формулы, но не вычисляет их: откройте результат в Excel/LibreOffice, пересчитайте и сохраните.

- **3 616 клиентов, 5 сегментов, 40 автоматических проверок.** История до 01.10.2011; holdout — октябрь–ноябрь 2011, 61 день.
- **47,70%** базы купили в будущем периоде. Ценные регулярные — **13,16% клиентов и 52,98%** будущего оборота базы после отмен.

- Исторические данные одного магазина и сезонный holdout. Причинный эффект CRM, прибыль и ROI не заявляются; индивидуальные клиентские строки не публикуются.

## Данные и определения

- Денежные суммы хранятся в целых пенсах. Сумма строки округляется один раз, half-to-even.
- Продажа: положительные количество и цена, номер счёта без `C`. Отмена: отрицательное количество, положительная цена, номер с `C`.
- Точные повторы сохранены: надёжного ID строки нет. Чувствительность результата к их удалению — £18 540,62 за отчётный период.
- Пропуски CustomerID исключены только из когорт, но не из денежных метрик. Их 24,9% исходных строк.
- Декабрь 2011 неполный и исключён. Декабрь 2010 служит историей для когорт. Первая наблюдаемая покупка не обязательно первая покупка клиента за всё время.
- M1 — покупка в следующем календарном месяце. Незавершённые окна — `NULL`, не ноль. Взвешенный показатель использует суммы клиентов, не среднее процентов.
- A/B-набор: 24 000 участников, seed 20261027, ITT, завершённое семидневное окно, SRM, z-test, Newcombe/Wilson CI. RPU — дополнительная метрика с нормальным приближением CI.
