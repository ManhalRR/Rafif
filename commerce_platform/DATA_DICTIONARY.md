# Commerce Analytics Platform — словарь данных

Источник — [UCI Online Retail II](https://doi.org/10.24432/C5CG6D), Chen, D. (2012), CC BY 4.0. Валюта GBP. Публикуются только агрегаты; исходные строки и Customer ID находятся в локальной папке `data/`.

## Периоды и единицы наблюдения

- Полный источник: 1 067 371 товарная/операционная строка на двух листах XLSX.
- Первый лист владеет датами `< 2010-12-01`; второй — `>= 2010-12-01`. Одинаковое перекрытие 1–9 декабря 2010 исключается из первого листа, но не из второго.
- Отчётный период `[2009-12-01, 2011-12-01)`: 24 полных месяца, последний — ноябрь 2011. Неполный декабрь 2011 исключён из витрин.
- Принятая строка — валидная операция после разрешения перекрытия и проверки даты, количества, цены и знака.
- Продажа: `Quantity > 0`, `Price > 0`, Invoice без префикса C. Отмена: `Quantity < 0`, `Price > 0`, Invoice с C.
- Заказ с продажами — уникальный составной ключ `[Invoice, Country, YYYY-MM]` хотя бы с одной принятой положительной строкой. Отмена не создаёт заказ. Повторы одного заказа не увеличивают его количество.
- Покупатель — положительный целочисленный Customer ID, совершивший хотя бы одну принятую продажу. Неизвестные ID участвуют в обороте и заказах, но не в клиентских метриках.

## Локальная SQLite-модель

| Таблица | Зерно / ключ | Назначение |
|---|---|---|
| `dim_date` | `date_id` YYYYMMDD, один календарный день | Дата, месяц, год, линейный индекс месяца `year × 12 + month − 1` |
| `dim_country` | `country_id`, один нормализованный Country | Страна источника; пустая страна = Unknown |
| `dim_product` | `product_id`, один StockCode | Код, детерминированное описание, категория формата кода |
| `fact_transactions` | `source_row_id = sheet:ExcelRow` | Принятые операции, ссылки на измерения, локальный Customer ID, количество, цена, денежная сумма |
| `mart_monthly` | Месяц | 24 месячных агрегата |
| `mart_country_month` | Страна × месяц с операциями | Географический фильтр и сверка оборота |
| `mart_products` | StockCode за весь отчётный период | Товарные/сервисные коды и ABC |
| `mart_cohorts` | Первый наблюдаемый месяц × возраст 0–11 | Размер когорты, активность и удержание |
| `mart_quality_monthly` | Месяц принятых операций | Число строк и отсутствие Customer ID |

Страна описывает поле источника, а не обязательно гражданство клиента или адрес доставки. Описание StockCode выбирается как самое частое в принятых строках; при равной частоте — первое лексикографически. Изменение описания не создаёт новый продукт.

`standard_stock_pattern` соответствует регулярному выражению `^\d{5}[A-Za-z]*$`. `service_or_nonstandard_code` означает иной формат кода; это эвристический технический флаг, а не достоверный товарный справочник. Сервисные, скидочные и нестандартные коды не удаляются из оборота автоматически. Даже код стандартного формата не гарантированно является физическим товаром.

## Денежные поля

Все суммы SQL/CSV/JSON целочисленные, в пенсах:

| Поле | Формула |
|---|---|
| `amount_pence` | Decimal(Quantity) × Decimal(str(Price)) × 100, округление half-even **один раз для строки** |
| `gross_pence` | Сумма amount_pence принятых положительных строк |
| `cancel_pence` | Минус сумма amount_pence принятых отрицательных строк; положительная величина отмен |
| `net_pence` | gross_pence − cancel_pence |

Это оборот после записанных отмен. Он не равен прибыли, марже или бухгалтерски признанной выручке. Себестоимость, расходы, налоги и правила признания выручки в источнике отсутствуют. Отмены относятся к дате их записи и не сопоставляются с исходными заказами. Отношение отмен к продажам — отношение денежных сумм, а не процент возвращённых заказов.

Цены XLSX считываются как числа, затем каноническое десятичное представление `str(Price)` передаётся в Decimal. Это не восстановление скрытой точности исходной учётной системы. Дальнейшая агрегация пенсов не использует float.

## Публичный `results/dashboard.json`

### `meta`

| Поле | Смысл |
|---|---|
| `source_rows` | Все строки двух листов до разрешения перекрытия |
| `accepted_rows` | Принятые строки после владения периодом и правил качества, включая неполный декабрь 2011 |
| `excluded_rows` | source_rows − accepted_rows: перекрытие плюс ошибки/неподходящие операции |
| `reporting_rows` | Принятые строки внутри 24-месячного отчётного периода |
| `source_sha256` / `source_zip_sha256` | Зафиксированные хеши XLSX / официального ZIP |
| `period_start`, `period_end` | Включительные даты отображения 01.12.2009–30.11.2011 |
| `months` | Полная упорядоченная сетка 24 месяцев |
| `countries` | Страны с принятыми операциями в отчётном периоде |

### `totals`, `monthly`, `country_month`

`orders` — число заказов с продажами по составному ключу. `known_customers` — уникальные известные покупатели **всего** периода, не сумма по месяцам. `products` — число StockCode с любой принятой операцией, в том числе только с отменой.

Оборот аддитивен по месяцам и странам. Заказы аддитивны по стране × месяцу благодаря определению ключа; это дополнительно сверяется с независимым агрегатом по уникальному ключу. Товарные counts заказов неаддитивны: один заказ содержит несколько продуктов.

`results/monthly.csv` имеет ровно пять колонок в порядке:

```text
month,gross_pence,cancel_pence,net_pence,orders
```

Модуль прогнозирования получает только эти агрегаты. Прогноз является отдельным расчётом и не изменяет фактические денежные итоги.

### `products`

Полный период, без фильтра страны/даты. `quantity` — сумма количества с учётом отрицательных отмен. `gross_share` — положительный оборот кода / весь положительный оборот. Если положительный оборот отсутствует, доля не определена и равна NULL, а не нулю. Сортировка: gross по убыванию, StockCode по возрастанию.

ABC использует долю **до** текущего кода: A, пока накопленная доля до строки меньше 80%; B до 95%; остальные C. Код, пересекающий границу, включается в текущий класс. Коды с нулевым gross — C. Равные суммы разрешаются по StockCode; одинаковый оборот может попасть в разные классы около границы. Поэтому класс A может содержать немного более 80% оборота. Это описательная классификация, не оценка рентабельности.

### `cohorts`

`cohort` — первый **наблюдаемый** месяц положительной покупки Customer ID в доступной истории. `size` — число покупателей когорты, повторяется для каждого возраста. `age` — разница календарных месяцев, от 0 до 11. `active_customers` — уникальные клиенты этой когорты с положительной покупкой в соответствующем месяце. `retention = active_customers / size`.

Будущий месяц после ноября 2011: `active_customers = null`, `retention = null`. Прошедший месяц без покупки: 0. M0 всегда 1. Известные клиенты без повторных событий остаются в знаменателе. Первая наблюдаемая покупка не обязательно первая в жизни клиента; история до декабря 2009 неизвестна.

### `quality`

| Поле | Охват |
|---|---|
| `rules` | Взаимоисключающие причины для всех строк источника: перекрытие, одна причина исключения или accepted |
| `missing_customer_rows`, `missing_customer_share` | Фактически пустой Customer ID во всём двухлистовом источнике до устранения перекрытия |
| `reporting_missing_customer_rows` | Неизвестный/некорректный ID среди принятых отчётных строк |
| `exact_duplicate_rows` | Точные повторы 8 исходных полей после владения периодом, до фильтра качества; дополнительная повторная строка считается один раз |
| `duplicate_net_sensitivity_pence` | Изменение net, если удалить все дополнительные точные повторы из выбранных периодов, с последующими теми же фильтрами качества/отчётного окна |
| `monthly` | Количество принятых отчётных строк и неизвестных ID по месяцам |
| `ownership_audit` | Размеры и даты листов, перекрытие, сравнение мультимножеств, строки после владения периодом, дубли во всём/выбранном источнике |
| `order_key_audit` | Invoice, встречающиеся в нескольких странах/месяцах, plain и composite counts |

Исходные пустые ID и невалидные непустые ID — разные определения; нормализация заменяет последние на неизвестные, не удаляя денежную операцию.

### `checks`, `insights`

`checks` содержит фактически пройденные сверки и тесты, а не заранее заданную константу. Подробности — `results/validation.json`. `insights` — наблюдение, интерпретация и следующий аналитический шаг. Рекомендации не объявляются внедрением, коммерческим эффектом или производственной системой.
